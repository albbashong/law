# 법령 근거 조회 에이전트 (law)

> "이 땅에 공장을 지어도 돼요?" 하고 물으면,
> 법전을 직접 펼쳐 **어느 법 몇 조에 그렇게 적혀 있는지** 찾아 주는 도우미입니다.

## 1. 어떤 프로젝트인가요? (초등학생도 읽을 수 있게)

### 도서관 사서 이야기

어느 마을에 아주 큰 도서관이 있어요. 이 도서관에는 나라에서 만든 **법 5,600여 권**과
시·군·구가 만든 **조례 16만여 권**이 꽂혀 있어요. 책을 펼치면 "제1조, 제2조…" 하는 작은 칸(조문)이
**970만 개**나 있지요.

사람들은 이런 걸 궁금해해요.

- "우리 할아버지 밭(주소)에 창고를 지어도 되나요?"
- "자연녹지에서는 땅의 몇 %까지 건물을 지을 수 있나요?"
- "술을 조금 마시고 운전하면 어떤 벌을 받나요?"

그런데 책이 너무 많아서 사람이 직접 찾기는 아주 힘들어요.
법은 서로 "자세한 건 저 책 몇 쪽을 봐"라고 가리키기도 해요.
그래서 한 권만 봐서는 답을 알 수 없을 때가 많아요.

그래서 **똑똑한 사서 로봇**을 만들었어요. 이 로봇은 이렇게 일해요.

1. **질문을 듣고** "아, 이건 땅에 무엇을 지을 수 있는지 묻는 거구나" 하고 알아차려요.
2. 주소가 있으면 **지도 기록(브이월드)**에서 그 땅이 어떤 땅인지 먼저 확인해요.
   (예: 자연녹지지역, 밭, 도로 옆)
3. **도서관 서랍**(법령 데이터베이스)에서 맞는 법과 조례를 꺼내요.
   "자세한 건 저쪽"이라고 적힌 화살표를 위아래로 따라가요.
4. 찾은 **원문을 그대로 보여 주면서** 대답해요.
5. 대답하기 전에 스스로 **검사**해요.
   - "내가 말한 숫자가 정말 책에 있는 숫자인가?"
   - "필지에 걸린 규제를 빠뜨리지 않았나?"

   틀린 곳이 있으면 다시 고쳐요.

> **중요한 약속:** 이 로봇은 "지어도 돼요 / 안 돼요"를 **판정하지 않아요.**
> "이런 법 조문이 있고, 이런 조건을 확인해야 해요"라고 **근거를 찾아 주는 것**까지가 일이에요.
> 최종 판단은 담당 공무원과 전문가가 해요.

### 그림으로 보면

```
 사람의 질문
     │
     ▼
┌──────────────────────┐   "어느 서랍을 열까?"   ┌───────────────────────────┐
│  사서 로봇 (에이전트)  │ ──────────────────────▶ │  도서관 서랍 (law-mcp)      │
│  law_review :7016    │ ◀────────────────────── │  법·조례·별표 원문 :7017    │
│  - 질문 이해          │    원문 + 조문 번호     │  - 조문 찾기 / 화살표 따라가기│
│  - 답 쓰기            │                         │  - 주소 → 땅 정보(브이월드)  │
│  - 스스로 검사        │                         └───────────────────────────┘
└──────────────────────┘                                      ▲
     │                                                        │ 매주 새 법으로 갈아 끼움
     ▼                                                        │ (법제처 Open API)
 근거 조문이 담긴 답                                    scripts/update.sh
```

## 2. 실제로 물어본 예시

아래는 시험 화면(playground)에서 실제로 물어보고 캡쳐한 화면이에요.

### 예시 ① 주소만 주고 "공장 지을 수 있어?"

> **질문:** 경상북도 영천시 금호읍 신월리 1-51에 공장 지을 수 있어?

로봇은 이렇게 답했어요.

1. 먼저 그 땅이 **자연녹지지역**이고, 지목은 **밭(전)**이며, **도로에 접해 있다**는 것을 확인했어요.
2. 공장을 허용하는 근거를 찾았어요.
   - 국토계획법 시행령 별표 17
   - 영천시 도시계획 조례 별표 16
3. 함께 알려 준 내용
   - 건폐율 20%, 용적률 100%
   - 농지전용 허가(농지법 제34조)
   - 공장설립 승인(산업집적법 제13조)
   - 필지에 걸린 다른 규제(도로구역, 가축사육제한구역)
4. 결론은 "조건부"예요. 그리고 **확인해야 할 조건 목록**을 정리했어요.

![주소로 공장 질문](docs/images/02-parcel.png)

### 예시 ② 건폐율과 근거 조문

> **질문:** 영천시 자연녹지지역 단독주택 건폐율이랑 근거 조문 알려줘

로봇은 시 조례(제56조)와 나라 시행령(제84조)을 나란히 보여 줬어요.
"성장관리계획이 있으면 30%까지"라는 예외도 함께 알려 줬어요.

맨 아래 `※ 다음 인용은 조회 결과로 확인되지 않았습니다`는 로봇이 **스스로 검사한 흔적**이에요.
따옴표로 옮긴 문장이 원문과 글자 하나까지 같지 않으면 "원문을 확인하세요"라고 표시해요.
펼쳐 둔 "도구 호출"에는 로봇이 어떤 서랍을 열었는지 그대로 남아 있어요.

![건폐율 질문](docs/images/03-ratio.png)

### 예시 ③ 아래에서 위로: "이 조례는 어느 법에서 왔어?"

> **질문:** 영천시 도시계획 조례 제25조의 상위 법령 근거가 뭐야?

조례에서 **위를 향한 화살표**를 따라가요. 그래서 이 조례가 국토계획법 시행령 제56조(별표 1의2)를 근거로 한다는 것을 찾아 줬어요.

![상위 법령 질문](docs/images/04-upper.png)

### 예시 ④ 생활 속 법률

> **질문:** 혈중알코올농도 0.03%로 운전하면 어떤 처벌을 받아?

도로교통법 제44조(기준)와 제148조의2(벌칙)를 찾아서,
"1년 이하의 징역 또는 500만원 이하의 벌금"이라고 원문 숫자 그대로 답했어요.

## 3. 무엇을 할 수 있나요?

| 이렇게 물으면 | 로봇이 하는 일 | 사용하는 서랍(도구) |
|---|---|---|
| "○○시 ○○지역에 카페 열 수 있어?" | 용도지역별로 지을 수 있는 건물 목록(시행령 별표와 시군 조례 별표)에서 찾기 | `building_basis` |
| "이 주소 땅은 어떤 땅이야?" | 브이월드로 용도지역, 지목, 면적, 규제를 확인하고, 필요한 전용허가와 규제 근거 조문 붙이기 | `parcel_zoning` |
| "자연녹지 건폐율·용적률은?" | 시행령 기준과 시군 조례 기준을 나란히 찾기 | `building_basis` |
| "건축법 제11조 원문이랑 하위 법령" | 조문 원문, 그리고 위(상위법)·아래(시행령·조례)로 이어지는 화살표 | `law_article` |
| "가축 사육 제한 거리는 어느 조례에?" | 법령과 조례 본문 검색 | `law_search` |
| "'공작물'이 법에서 뭐야?" | 법령의 정의 조문 찾기 | `law_definition` |

이 로봇이 **하지 않는 일**

- 허가 여부 판정
- 지도 조작
- 토지대장과 건축물대장의 상세 조회
- 법령 원문(HWP/PDF) 파일 저장

## 4. 프로젝트 구성 (어른용)

```
law/
├── mcp/                 법령 MCP 서버 (law-mcp, :7017) — 공식 mcp SDK, streamable HTTP
│   └── src/law_mcp/
│       ├── tools/       building_basis · parcel_zoning · law_article · law_search · law_definition
│       ├── engine/      위임·인용 따라가기(follow), 별표 해석, 필지 규제 근거(regulations) 등
│       ├── store/       lawdb.sqlite 읽기 (FTS 검색)
│       └── clients/     브이월드 API
├── agent/
│   ├── runtime/         A2A 에이전트 런타임 (:7016) — 도구 루프, 답 검증(인용·수치·누락 규제), 되묻기
│   ├── law_review/      이 에이전트의 설정: agent.yaml, 프롬프트, 분야 지침(domains/), 쉬운 설명 틀(story_forms/)
│   └── agent-spec/      에이전트 명세
├── indexer/             법제처 원문 → 조문 단위·별표 항목·인용 관계로 쪼개 lawdb.sqlite 만들기
├── scripts/             원문 받기(fetch_*), 색인 만들기(build_index), 정기 갱신(update.sh, 예약 설치)
├── eval/                평가 세트·채점, 시험 화면(playground.py, :7018)
├── deploy/              podman compose 배포 — 자세한 내용은 deploy/README.md
└── docs/                설계(specs), 구현 계획(plans), 자체 시험 보고서, 연동 요청서
```

### 데이터

| 항목 | 규모 |
|---|---|
| 법령(법률, 시행령, 시행규칙) | 약 5,600건 |
| 자치법규(조례, 규칙) | 약 16만 2천 건 |
| 조문·항·호·목·별표 항목 단위 | 약 970만 개 |
| 위임·인용·법제처 연계 관계 | 약 490만 개 |
| `data/lawdb.sqlite` | 약 7~8GB (git에는 넣지 않음) |

원문은 [법제처 국가법령정보 Open API](https://open.law.go.kr)에서 받아요.
필지 정보는 [브이월드](https://www.vworld.kr) API에서 가져와요.

### 설계 원칙

- **원문 우선:** 답에 쓰는 숫자와 따옴표 인용은 조회한 원문과 기계적으로 대조해요. 맞지 않으면 한 번 되돌려 고치게 하고, 그래도 다르면 "원문 확인 필요"라고 표시해요.
- **하드코딩 금지:** 특정 질문이나 키워드에 맞춘 규칙을 두지 않아요. 연결 관계는 법령 데이터에서 찾아요(조문 제목, 정의 조문, 인용 관계). 단, 바뀌면 안 되는 법률 용어 자체는 그대로 써요.
- **판정하지 않음:** 근거, 조건, 남은 확인 사항을 제시하고 결론은 조건부로 써요.

## 5. 실행해 보기

### 준비물

- Python 3.12, [uv](https://docs.astral.sh/uv/)
- `data/lawdb.sqlite`
  - 이미 만든 파일을 옮겨 오거나, `scripts/update.sh`로 새로 만들어요.
  - 처음부터 만들려면 법제처 OC가 필요해요.
- OpenAI 호환 언어 모델 서버
  - 개발 환경에서는 vLLM으로 띄운 gpt-oss-120b를 써요.
- 브이월드 API 키
  - 주소로 묻는 기능에만 필요해요.

### 설정 파일

키와 주소는 **git에 올리지 않는** 파일에만 둡니다.

```bash
cp agent/law_review/.env.example agent/law_review/.env   # VLLM_BASE, VLLM_MODEL, VLLM_API_KEY
# 저장소 루트 .env 에 VWORLD_API_KEY=... (주소 조회), LAW_API_OC=... (법령 갱신)
```

### 로컬 실행

```bash
agent/scripts/run.sh start     # law-mcp :7017 + law_review :7016 (로그는 logs/)
agent/scripts/run.sh status
python3 eval/playground.py     # 시험 화면 → http://localhost:7018
```

### 컨테이너 배포

```bash
cd deploy && podman compose up -d --build
```

자세한 내용은 [deploy/README.md](deploy/README.md)를 보세요. 법령 DB 주간 자동 갱신도 거기에 있어요.

### 다른 에이전트에서 부르기

이 에이전트는 [A2A](https://a2a-protocol.org) 규격을 따라요.

- 에이전트 카드: `http://<호스트>:7016/.well-known/agent-card.json`
- 질문 보내기: `POST /message:send`

```bash
curl -s localhost:7016/message:send -H 'Content-Type: application/json' -H 'A2A-Version: 1.0' -d '{
  "message": {"messageId": "1", "role": "ROLE_USER",
              "parts": [{"text": "영천시 자연녹지지역 단독주택 건폐율 알려줘"}]}}'
```

### 테스트

```bash
(cd mcp && uv run pytest -q)
(cd agent/runtime && uv run pytest -q)
```

## 6. 아직 부족한 점

로봇도 아직 배우는 중이에요. 지금 알고 있는 약점은 이렇습니다.

- **말투에 흔들려요.** 같은 질문이라도 "괜찮은 거지?"처럼 물으면 답이 달라질 때가 있어요.
  - 일상어로 물으면 맞는 법 조문을 못 찾기도 해요(예: "줄 안 매면 벌금").
- **조건 연결이 약해요.** 필지 정보에 "성장관리계획구역"이 있는데도, 결론에서 그걸 반영하지 못할 때가 있어요.
- **조례 속 줄임말:** 조례에 쓰인 "법", "영"이 어느 법령을 가리키는지 헷갈릴 때가 있어요.

그래서 답에는 항상 근거 조문이 붙어 있어요. **중요한 결정 전에는 원문을 꼭 확인하세요.**
