# 코딩 에이전트를 위한 지시

이 폴더로 **A2A 에이전트 하나를 만듭니다.**

## 읽는 순서 — 이대로만 읽습니다

1. `README.md` — 무엇이 표준이고 무엇이 이 플랫폼의 관례인지
2. `SPEC.md` **1장 → 2장 → 3장** — 만들 것과 지켜야 할 요건
3. `reference/stub_agent.py` — 요건을 지키는 최소 구현. **이것을 본뜨면 됩니다**
4. 막힐 때만 `SPEC.md` 5장(만들 때의 안내), 6장(도구·프롬프트 설계)

`reference/a2a.proto` 와 `reference/specification.md` 는 **통째로 읽지 않습니다.** 규격이 의심될 때 해당 절만 찾아봅니다.

## 만들기 전에 사람에게 물어볼 것

추측하지 말고 **반드시 물어봅니다.**

| 물을 것 | 왜 |
| --- | --- |
| **어떤 도메인의 에이전트인가** | 이름·설명·스킬이 여기서 나옵니다 |
| **어떤 도구를 쓰는가** | 이미 있는 도구의 주소와 목록. 없으면 만들 수 없습니다 |
| **모델 엔드포인트** | 도구 호출을 지원해야 합니다 |
| **포트** | 비어 있는지 확인하고 씁니다 (5.7절) |
| **확장 URI 의 도메인** | 4.1절. **예시 값을 그대로 쓰면 안 됩니다** |
| **어느 오케스트레이터에 붙는가** | 4장 프로파일을 따를지가 갈립니다 |

## 지켜야 하는 것과 아닌 것

| | |
| --- | --- |
| **2장 · 3장** | **필수.** 안 지키면 부적합입니다 |
| 4장 | 이 플랫폼의 프로파일. **안 따라도 A2A 적합합니다** — 붙을 곳이 요구할 때만 |
| 6장 · 8장 | 잘 돌게 만드는 지침. 요건이 아닙니다 |
| 5장 · 7장 | 만들 때의 안내와 점검기 사용법 |

## 다 만들면 반드시 점검합니다

```bash
python3 conformance_check.py http://localhost:<포트>
python3 conformance_check.py http://localhost:<포트> --probe "<이 에이전트가 받을 법한 발화>"
```

- **종료 코드 0 이 나올 때까지 고칩니다.** 1 이면 A2A 부적합입니다.
- 실패마다 `SPEC.md` 의 절 번호가 붙습니다. 그 절을 읽고 고칩니다.
- **`--probe` 를 반드시 한 번은 돌립니다.** 되묻기 루프가 닫히는지는 이것으로만 잡힙니다.
- 프로파일(4장) 미준수는 종료 코드에 영향이 없습니다. 붙을 곳이 요구하지 않으면 그대로 둡니다.

## 흔히 틀리는 것

- 예시 도메인(`<도메인>`)을 그대로 두기 — 확장이 무시됩니다. 오류는 안 납니다
- 스킬의 `hints` 를 빼기 — 병렬 실행이 조용히 죽습니다 (4.1.1절)
- `description` 에 **"…는 이 에이전트가 아니다"** 를 안 쓰기 — 남의 일이 들어옵니다 (6.2절)
- 되묻고 나서 답을 받았을 때 이전 상태를 안 들고 있기 — 같은 질문이 되돌아옵니다 (2.5절)
- 카드에 `streaming: true` 라 해 놓고 `/message:stream` 을 안 만들기 (2.3.2절)

## 하지 않는 것

- `reference/` 안의 파일을 고치지 않습니다. 표준 정본입니다
- `SPEC.md` 를 고쳐 요건을 맞추지 않습니다. 코드를 고칩니다
